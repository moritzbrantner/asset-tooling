# Tileable surface recipes

`asset-tooling/recipes/surface-textures` supplies a soil/tilled-soil/rock/wood slice of #131. It composes the existing periodic bilinear height generator and wrapped normal processor with `image.procedural.height.surface@1` (two-scale height mixture) and `image.scalar.color-ramp@1` (opaque scalar-to-RGB ramp). Each operation is independently callable and exposes its descriptor and build-identity function for workflow registration. No network, model service or Blender is required.

```ts
import { executeSurfaceTextureRecipe, SURFACE_TEXTURE_PRESETS } from "asset-tooling/recipes/surface-textures";

const result = await executeSurfaceTextureRecipe(objectStoreRoot, {
  ...SURFACE_TEXTURE_PRESETS["soil-fine"],
  gridX: 4, gridY: 16, detailWeight: 100,
}, { channels: ["color", "height", "normal", "roughness"] });
```

The absolute object-store root is explicit. Recipes require version 1, repeat sampling, a decimal seed, dimensions, coarse/detail grid counts, detail weight, height range, RGB endpoint palette, normal strength and roughness range. Grids measure cycles per tile axis rather than meters. Each grid is bounded by 256 and its image dimension, dimensions by 4096, byte ranges by 0–255, and normal strength by 1–1024. Height and roughness ranges must be ordered; constant ranges are supported. Unknown fields fail. Reduce grid counts explicitly when requesting a smaller resolution; they are never silently clamped.

Height mixes coarse seed N and detail seed N+1 using an integer weight in 0–255, then remaps the quantized value into the declared height range. Zero detail weight skips the detail generator. Color and roughness interpolate endpoints using the resulting byte scalar. The original directional soil preset supplies anisotropic noise variation. The optional furrow composition below supplies regular ridge/trough cross-sections. The rock presets expose smooth/grainy/layered patterns rather than a scanned-rock fidelity claim.

Select any non-empty unique subset of channels. Height is the common dependency; a height-only invocation executes no palette, roughness or normal stage. The result retains the editable normalized recipe/hash, independent channel AssetRefs, component identities and every operation build/observation. Palette edits do not enter height, normal or roughness build parameters. Normal-strength edits change only normal derivation. Repeated and cold-store builds reproduce identical results under the documented built-in algorithms; stored bytes are reconciled rather than overwritten. This slice replays computation on invocation and uses the existing content-addressed store; it does not claim computation-cache hits or add another cache framework.

## Explicit component preservation

`executePreservedSurfaceTextureRecipe` provides the first texture slice of #139. Supply accepted steps from the full recipe as explicit component locks, using the same immutable AssetRefs and build identities:

```ts
import { executePreservedSurfaceTextureRecipe } from "asset-tooling/recipes/surface-textures";

const accepted = await executeSurfaceTextureRecipe(objectStoreRoot, recipe);
const stepFor = (field: string) => accepted.steps.find(step => step.output.metadata.field === field)!;
const recolored = await executePreservedSurfaceTextureRecipe(objectStoreRoot,
  { ...recipe, low: [75, 28, 12], high: [215, 178, 119] },
  { preserve: { height: stepFor("height"), normal: stepFor("normal"), roughness: stepFor("roughness") } });
```

The optional `channels` selection has the same meaning as the full recipe. Height may be locked as a dependency even when it is not selected as an output; locks for other unselected channels are rejected. A dependent lock requires a height lock. Omitting a lock explicitly regenerates that component. Every supplied lock must match the entire current operation/build identity, including relevant parameters, source AssetRef and implementation/tool identity. Stale locks diagnose which component needs regeneration instead of silently keeping its old shape. All locked payloads, dimensions, alpha, complete producer-owned metadata and observations are verified before any new channel computation/writing. Height source-hash metadata must match its declared coarse/detail component evidence, whose current builds, full output metadata, content hashes/lengths and opaque grayscale dimensions are also checked. Every declared component blob must remain available and intact. Additional metadata/observations are rejected instead of entering downstream identities. In particular, corrupt normals cannot allow a preceding color output to be promoted.

This is caller-selected reuse, not automatic cache lookup or a new scheduler/database. Preserved steps and objects remain untouched; underlying height/noise and preserved channel operations are not executed. Only omitted channels run through the existing processors. Palette-only edits reuse height/normal/roughness; normal-strength edits can reuse height/color/roughness. Editing a locked height seed/frequency/range, locked normal strength or locked roughness range fails deliberately. Release the affected locks to request that edit. The original full recipe retains its result shape and executes every selected dependency, providing a cache-independent replay/reference path.

The partial result adds `execution`: ordered executed/reused stages, operation counts and generated image-pixel counts. Height counts its coarse generator, optional detail generator and mixture; each other channel counts one processor. Read/validation work is not generation. These are execution observations, not a second content identity. Accepted build-to-output associations remain declared provenance; they are not signed evidence or a proof of functional correctness. An independent full rebuild must compare canonical results before claiming exact reproducibility. Serialized accepted snapshots work after restart only while their current implementation identity and verified objects still match.

Run `bun examples/surface-preservation/build.ts` to produce a gray-to-warm-rock recolor and a separate stronger-normal edit under ignored `.artifacts/surface-preservation/`. Each edit executes one operation and reuses five at the default two-scale settings. The example compares both canonical results with independent cold full builds, records actual newly stored canonical-object bytes separately from operation/pixel counts, and encodes six inspectable PNGs with the existing declared FFmpeg codec identity. `execution.json` records the observed run: its byte-write counts can change between cold and warm runs, while canonical refs and unchanged PNGs reconcile. `python scripts/surface-preservation-review.py` composes the actual images into a tiled inspection sheet. These are texture-only edits; no mesh generator executes and no silhouette-displacement claim is made.

An isolated generator spy throws if a partial recolor executes a noise operation while the accepted coarse/detail blobs remain valid, independently detecting hidden height regeneration. Altered component hashes/lengths, missing/corrupt bytes and inconsistent dimensions fail before writing. Edit/reorder/channel-selection/undo and deserialized snapshots match cold results. Changed locks, altered channel metadata and corrupt payloads fail without new objects. Run `bun test test/surface-preservation.test.ts test/surface-texture-recipes.test.ts test/procedural-textures.test.ts test/material-operations.test.ts`, then the ordinary gate. This bounded slice keeps #139 open for mesh/foliage/terrain/sprite families, stable component seed groups, cancellation/recovery, workbench locks and real consumer acceptance.

## Channel and sampling contracts

Color is sRGB. Height and roughness are opaque grayscale UNORM8 scalar **data**; normals are tangent-space XYZ UNORM8 **data**, with **negative Y**, matching `image.normal.from-height@1`. All currently use the existing canonical RGBA8 transport (whose document says sRGB); each standalone channel AssetRef carries `field`, `sampling` and `channelColorSpace` metadata (normal also carries `normalYAxis`), and those explicit channel semantics require data sampling without an sRGB transfer for scalar/normal channels. Use `texture.orm.pack@1` for the existing linear packed ORM transport and `material.pbr.bundle@1` with `normalYAxis: "negative"`. AO and metallic are not generated or inferred from noise. This recipe does not automatically invent AO/metallic maps or a material bundle. #124 owns texture-set validation and runtime format variants.

Sampling covers `[0,width) × [0,height)`; the first/last texels need not equal. Wrapped derivatives cross the periodic boundary. No mipmap-generation or world-space height/displacement contract is supplied. Repeat-safe consumer sampling/mipmaps and physical height scale remain explicit follow-ups.

Run `bun examples/surface-textures/build.ts` from any working directory to generate all twelve controlled presets, four channel PNGs per preset and `builds.json` under the repository's ignored `.artifacts/surface-textures/`. PNG encoding uses the existing explicit FFmpeg operation and records its runtime identity; exact PNG replay is scoped to that recorded implementation. Canonical RGBA8 replay does not require FFmpeg. Repeated example builds preserve byte-identical files and metadata; changed files are staged before atomic replacement. Generated outputs and evidence remain disposable.

Tests cover independent scalar endpoints/interior bytes, the existing pinned periodic-noise fixture, constant scalar/normal references, wrapped normals compared with the center of an independently repeated 3×3 height image, odd/tiny dimensions, invalid/colored/transparent/corrupt input, selected stages, cold-store replay and independent channel invalidation. Run `bun test test/surface-texture-recipes.test.ts test/procedural-textures.test.ts test/material-operations.test.ts`, followed by `bun run check`.

The twelve exported presets are deeply frozen recipe content. Create editable variants by spreading a preset and replacing changed values; replace `low`/`high` arrays rather than mutating them. Registered operation descriptors are recursively frozen too. They provide three noise-soil, three tilled-soil, three rock and three directional wood variations with fixed seed and changed controls. Tiled inspection is technical/artifact evidence; it is not My Farm camera acceptance. Consumer repositories remain read-only in this loop. My Farm currently renders Field Plot using constant-color materials in `packages/game-scene/src/assets.tsx`; integration belongs to my-farm#125. ## Regular tilled furrows

Add `furrows: { axis: "x", count: 4, depth: 200, softness: 3 }` to a surface recipe or directly to `image.procedural.height.surface@1` parameters. All four controls are required when the optional object is present; omitting it preserves original noise-only pixels. The existing height operation uses implementation 2, `periodic-two-scale-unorm8-mix-stripes-v2`, with the same public operation version and compatible optional parameter extension. Source/tool identity distinguishes earlier implementations. Accepted component locks must match the current producer identity; stale locks require explicit regeneration.

`axis` is the image coordinate along which the cross-section changes: x gives vertical texture rows, y gives horizontal rows. `count` is full ridge/trough cycles per tile, 1–64 and at most half that axis's texel count. That axis needs at least two texels. This is a pattern-scale contract, not physical furrow spacing. `depth` is a 0–255 profile blend weight, not meters of displacement. Zero retains the original grain; 255 replaces grain with the cross-section. The existing coarse/detail noise mixture remains independent of the profile controls; the mixed scalar is remapped through the original height range afterward.

The profile composes the existing two-color stripe kernel at 16 samples per cycle (eight trough/eight ridge), two passes of existing box blur and crop, quarter-turn orientation and nearest pixel-center resize. `softness` is an integer blur radius of 0–3 **profile samples**, independent of output resolution. Zero disables blur; two equal blur passes soften the cross-section into rounded transitions. A repeated one-dimensional source supplies the middle tile for blur, so its clamp border never affects the periodic profile. Small/odd dimensions sample full cycles without duplicating endpoint texels; limited resolution can quantize the shape. The native height and derived wrapped normals remain opaque data with the existing channel and negative-Y conventions. No new noise, convolution, normal or material kernel is introduced.

The deeply frozen `soil-tilled-shallow`, `soil-tilled-deep` and `soil-tilled-crosswise` presets use the same seed, varying depth/normal intensity and, for crosswise, direction/count; all three use softness 3. They retain the existing separate channel refs and explicit preservation path. Recoloring accepted tilled height/normal/roughness executes only the color stage. Changing a locked profile rejects its stale height build. Full and cold runs remain the independent replay path.

Run `bun examples/tilled-soil/build.ts` for three actual four-channel PNG sets, cold-replay evidence and complete PBR GLBs on an explicitly authored +Y-up, two-triangle review quad. The quad has UV0 and tangents and is imported through the existing production glTF operation; it represents material inspection, not a displaced production Field Plot. Normal conversion, explicit neutral unoccluded AO/dielectric metallic inputs, ORM packing and finishing use the existing operations. The selected package is verified through `asset-tooling/operations/bundle`; repeated output files reconcile. No network or Blender is required to produce the textures. The optional native review uses `scripts/tilled-soil-review.py` through pinned Blender and displays two UV repeats under identical camera/light settings without altering packaged bytes. This is artifact evidence; My Farm's actual Field Plot integration and camera approval remain with my-farm#125.

`bun test test/tilled-soil.test.ts test/surface-texture-recipes.test.ts test/surface-preservation.test.ts test/procedural-image.test.ts test/procedural-textures.test.ts` covers independent square/soft cross-sections, pinned grain/depth/range arithmetic, both axes, odd sizes, pre-write invalid controls, cold replay, preserved recoloring and wrapped normals against an independently repeated heightfield. ## Directional wood grain

`wood-long-grain`, `wood-short-grain` and `wood-cross-grain` use the same seed, brown palette, detail weight and channel ranges. Long grain has coarse grids 24×1 and detail grids 96×2; short grain increases lengthwise variation to 24×6 and 96×12; crosswise grain uses 1×24 and 2×96. More cycles on x make predominantly vertical grain, and more cycles on y make predominantly horizontal grain. These are anisotropic periodic-noise approximations. Growth rings, knots, bark and a physical species/finish model remain follow-ups. The existing height implementation and previous presets retain their algorithms and controls.

Use the existing height/detail grid counts to edit grain frequency and direction; palette, normal strength and roughness remain independent controls. Counts measure cycles per tile, with the resolution bounds above. Recoloring explicitly preserved height/normal/roughness executes one color operation and reuses five operations at the default two-scale settings. Full cold rebuilds compare the complete canonical result independently.

Run `bun examples/wood-surfaces/build.ts` to produce fifteen PNGs (four channels and a preserved recolor per preset), canonical pixel files, complete source/processor evidence and three PBR GLBs under ignored `.artifacts/wood-surfaces/`. Finishing reuses the existing authored review quad from `examples/tilled-soil/plane.gltf`, including its original `soil-surface` slot name. It verifies unchanged indices, all attributes, node transforms and hierarchy against the imported quad. Explicit neutral AO and dielectric metallic channels feed the existing ORM/material operations; no geometry generator runs. Each texture recipe, recolor, PNG and material finish is compared with an independent cold replay. The selected GLBs export and verify through the existing static bundle profile.

`python examples/wood-surfaces/review.py` independently checks PNG hashes/lengths and every decoded pixel against the canonical RGBA images, then composes two repeats into an inspection sheet. With the repository's pinned Blender available, `bun examples/wood-surfaces/render.ts` generates and verifies three native renders through the existing static-GLB render backend using identical camera/light parameters. Run the review script again for a native render sheet. It checks each render's spec/receipt, current GLB input pin, script bytes and output hash before displaying it. Stale or invalid evidence fails and removes the old native sheet; missing renders omit the sheet. Scripts anchor paths to their source files and reconcile identical outputs; optional render dependencies do not enter texture generation. These are review artifacts, not consumer-camera approval or physical displacement evidence.

`bun test test/wood-surfaces.test.ts test/surface-texture-recipes.test.ts test/surface-preservation.test.ts test/procedural-textures.test.ts` covers a pinned one-dimensional grain fixture, fixed-seed direction/length changes, cold replay, preserved recoloring and odd-size wrapped normals against an independently repeated height image. Run `bun run check` afterward.
